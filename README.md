# A股多策略选股回测系统

一套可重复执行的 A 股选股策略研究工具：自动拉取沪深300 成分股日线 → 跑 5 个技术面选股策略 → 检验「同时多只票触发时该买谁」→ 输出当日信号清单与可视化报告。

**每天只想知道「今天买哪几只」：**

```bash
python3 run.py pick
```

补数据（只补落后的票）→ 算当日信号 → 终端直接打印每策略前 5 名 → 刷新看板。约 6 秒（有新交易日时约 1 分钟）。
产物在 `reports/signal_board.html`、`reports/signal_snapshot.md`。

**想重新回测一遍（改参数、看长期表现）：**

```bash
python3 run.py all
```

跑完打开 `reports/regime_report.html`（策略对比）与 `reports/signal_board.html`（今日信号）。

仓库地址：<https://github.com/zhangyun814/tdx>

```bash
git clone https://github.com/zhangyun814/tdx.git
cd tdx
```

## 1. 环境要求

- Python 3.10+（用到 `tomllib`，3.11+ 免装依赖；3.10 需 `pip install tomli`）
- 依赖：`pandas` `numpy` `matplotlib`
- 数据源：`westock-data` 命令行工具（提供 `scripts/index.js` 的那一层目录）

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python3 run.py doctor          # 自检：数据源、node、股票池、数据目录
```

`doctor` 会打印数据源路径与全部生效参数。如果数据源没被自动找到，在 `config.toml` 里指定：

```toml
[data]
westock_dir = "/path/to/westock-data"
node_bin    = "/path/to/node"
```

也可以用环境变量 `WESTOCK_DATA_DIR` / `QUANT_NODE_BIN` 覆盖（优先级最高）。

## 2. 命令

| 命令 | 作用 | 耗时（300 只 / 4 年） |
|---|---|---|
| `python3 run.py pick` | **只选股**：补数据 + 当日候选 + 看板 | 约 6 秒（有新交易日约 1 分钟） |
| `python3 run.py all` | 抓数 + 回测 + 检验 + 信号 + 报告，全流程 | 首次约 4 分钟（含下载），之后约 10 秒 |
| `python3 run.py fetch` | 只更新数据（成分股 + 日线 + 合并面板） | 增量约 10 秒；`--refresh` 全量约 3 分钟 |
| `python3 run.py backtest` | 只用本地数据重跑回测 | 约 7 秒 |
| `python3 run.py analysis` | 排序规则有效性检验 | 约 4 秒 |
| `python3 run.py signal` | 当日信号快照（md + json） | 约 2 秒 |
| `python3 run.py report` | 渲染对比报告（仪表盘 + 3 张图） | 约 3 秒 |
| `python3 run.py board` | 渲染信号看板 | 约 1 秒 |
| `python3 run.py history` | 查看历次运行摘要（年化 / 回撤 / 信号数变化） | 即时 |
| `python3 run.py doctor` | 环境自检 | 即时 |

常用参数（对所有命令生效）：

```bash
python3 run.py all --start 2023-01-01 --end 2025-12-31   # 改评估区间
python3 run.py all --index sh000905                      # 换成中证500 成分股
python3 run.py backtest --max-positions 8                # 改持仓上限
python3 run.py backtest --regime-window 120              # 改市场状态均线
python3 run.py fetch --refresh                           # 强制全量重下（约 3 分钟）
python3 run.py all --skip-fetch                          # 跳过抓数，直接用本地数据
python3 run.py all --no-archive                          # 不留历史快照，只更新最新结果
```

> 数据每天都在变，`eval_end` 默认取「数据里最后一个交易日」，所以不需要手动改日期。

### 只想选股，不想回测

python3 run.py pick --index sh000905  # 换池子（中证500）

## 2.5 重复运行会不会覆盖上一次结果？

分两部分看：

**报告（`reports/` 根目录）——会覆盖。** `regime_report.html`、`signal_board.html`、各策略的
`_equity.csv` / `_trades.csv` / `_summary.json` 都是固定文件名，每次运行原地重写。
根目录永远代表「最新一次」，方便你直接打开。

**历史快照——不会覆盖。** 每次 `all` 结束后会自动把这一批产物复制一份到
`reports/runs/<年月日_时分秒>/`，并在 `reports/history.csv` 追加一行摘要
（数据截至日、市场状态、五策略平均年化/回撤/夏普、最优策略、信号数）：

```bash
python3 run.py history          # 打印历史表，看每次跑出来的东西怎么变的
```

```
运行时间            数据截至    状态  年化     回撤     夏普    信号  最优策略
2026-10-19 21:39:17 2026-10-19  OFF   12.75%   27.04%   0.569   87    S2 唐奇安通道突破（年化 24.40%）
2026-10-16 21:30:00 2026-10-16  OFF   11.42%   27.20%   0.493   74    S2 唐奇安通道突破（年化 22.80%）
```

- 只留最近 `keep_runs` 份（`config.toml` 里改，默认 60），更早的自动删掉
- 不想归档就加 `--no-archive`；想手动清理直接删 `reports/runs/`
- **注意**：数字变了先看 `数据截至` 是否变了。同一份数据连跑两次结果完全一致；
  数据一更新（多了一根 K 线、补了一只停牌股），历史区间跟着延长，年化/夏普就会小幅漂移

## 2.6 数据会不会过期？

不会。`fetch` 默认是**增量更新**而不是「有文件就跳过」：

1. 先刷新基准指数（只有 1 只，成本极低），拿它的最后一个交易日当作「应有最新日」
2. 逐只检查 `data/raw/*.md` 里的最新日期，**已经追平就复用，落后才重下**
3. 所以每天跑一次既不会重复下载 300 只票，也不会拿着上周的数据算出「今日信号」

代价是每天第一次跑会比纯缓存慢一些（要重下当天有更新的票）；`--refresh` 才会无条件全量重下。

## 4. 五个策略

全部为多头、纯技术面，信号在**当日收盘确认、次日开盘成交**。

| 编号 | 名称 | 类型 | 买入 | 卖出 | 最长持有 |
|---|---|---|---|---|---|
| S1 | 双均线趋势跟踪 | 趋势跟随 | MA20 上穿 MA60（金叉） | MA20 下穿 MA60（死叉） | 不限 |
| S2 | 唐奇安通道突破 | 趋势突破 | 收盘价突破前 20 日最高 | 收盘价跌破前 10 日最低 | 不限 |
| S3 | RSI 超卖反转 | 均值回归 | RSI(14) < 30 | RSI(14) > 60 | 20 日 |
| S4 | 布林下轨回归 | 均值回归 | 收盘价跌破布林下轨（20, 2σ） | 回到中轨上方 | 30 日 |
| S5 | 量价放量突破 | 事件驱动 | 涨幅 > 3% 且量能 > 2×20日均量 | 跌破 MA10 | 15 日 |

**同一策略同日多只票触发时，按排序分数取前 N 只**（N = `max_positions`）：

| 策略 | 排序依据 |
|---|---|
| S1 / S2 | 近 20 日涨幅（越强越优先） |
| S3 | RSI 由低到高（越超卖越优先） |
| S4 | 收盘价偏离下轨幅度（跌得越狠越优先） |
| S5 | 当日涨幅（越猛越优先） |

排序分数**不是收益预测**，它只决定「同一天触发的信号里谁先买」。这个排序到底有没有用，程序会自己用历史数据检验（见第 6 节）。

## 5. 市场状态过滤（三种用法）

判断规则：**基准指数当日收盘价 > 自身 N 日均线 → ON（允许开新仓），否则 OFF**。用当日收盘与当日均线比较，收盘确认、次日生效，不含未来信息。

三种用法在报告里横向对比：

| 模式 | 规则 |
|---|---|
| `base` 原版 | 不判断市场状态 |
| `reg` 只过滤开仓 | OFF 时不开新仓，已持仓按原策略退出 |
| `regx` 过滤+清仓 | OFF 时不开新仓，且 ON→OFF 当日收盘挂单，次日开盘起**持续挂单**清仓 |

为什么必须「持续挂单」：遇到开盘跌停或停牌，一次性信号会被丢弃且不再重试，持仓会滞留在 OFF 区间。改成未成交则每日重挂后，除停牌这类客观卖不掉的情况，清仓滞后都在 1 个交易日内。

## 6. 排序有效性检验（`analysis`）

回答「同一天多只票触发，怎么判断哪只更好」，分三层：

1. **top1 口径**：只买排序第 1 名，后验收益是否优于当天全部信号的平均（配对 t 检验 + Spearman IC）。
2. **top5 口径**：实盘买满 N 只，对比 6 种排序规则——当前规则 / 反向 / 低波动 / 量比 / 相对强度 / 随机。
3. **分层检验**：第 6 名之后（排队名单）是否真的更差，只统计「当日候选 ≥ N 只」的交易日以控制样本偏差，并输出「信号密集日 vs 稀疏日」的后验收益差作为混淆检验。

判定文字（有效 / 接近无效 / 方向反了 / 单调递减 / 正好相反 / 样本不足）由数据自动生成，不写死结论，因此换区间、换股票池后不会出现「文字与图表矛盾」。

## 8. 回测口径与假设

- **股票池**：指数当前成分股（默认沪深300），用当前成分回溯历史 → **存在幸存者偏差**，收益被系统性高估
- **区间**：`eval_start`（默认 2022-07-01）到数据最后一天；之前的数据只用于指标预热，不产生交易
- **执行**：信号当日收盘确认，次日开盘成交；A 股 T+1；100 股整手
- **仓位**：最多同时持有 `max_positions` 只，单票目标权重 `weight`（默认 20%，等权）
- **成本**：双边佣金 3bp + 卖出印花税 5bp；**未计滑点与冲击成本**
- **涨跌停**：开盘涨停不买、开盘跌停不卖（按板块上限估算：主板 10%、创业板/科创板 20%、北交所 30%）
- **停牌**：开盘价缺失视为无法成交，卖单继续挂
- **期末**：最后一天强制平仓，所有持仓计入成交记录

### 已知局限

1. **幸存者偏差**：用当前成分股回看历史，等于提前剔除退市与被调出的股票。
2. **日线近似**：无法还原盘中顺序，大波动日的成交价会明显偏离。
3. **未设止损 / 无基本面过滤**：不识别业绩暴雷、退市风险；均值回归类在单边下跌中会持续接飞刀。
4. **参数未寻优**：均线、通道、RSI 阈值都是教科书默认值，未做稳健性扫描，换个区间可能失效。
5. **空仓摊薄波动率**：见上一节夏普说明。
6. **未考虑融资成本、税费差异、停复牌跳空**。

## 9. 关于 `quant/vendor/`

`vendor/` 里是复用的第三方渲染组件（HTML 仪表盘模板与标准导出器），来自策略回测专家包的 `reference/` 目录，用于保证输出格式统一。它们不是本项目原创代码，升级时整体替换即可，不要在里面改业务逻辑。

如果你要分发本项目，请自行确认这些组件的授权条款；也可以把 `report.py` 换成自己的渲染实现，其余模块（engine / analysis / signals）不依赖它们。

## 10. 与早期手工版本的数字差异

本程序是早期一次性脚本的重构版，口径一致但有两处有意改进，重跑后个别数字与历史记录会有微小差别：

1. **涨跌停判断的首日基准**：旧版回测首日的「前一收盘价」为空，导致首日不判断涨跌停；本版用预热段最后一天收盘价初始化，首日也正常判断。
2. **数据末端**：默认取数据里最后一天，比手写固定日期更新；期末强制平仓价格随之变化，累计收益会有小幅差异。
3. **2 个信号日的 IC 不计入**：只有 2 只候选时 Spearman 恒为 ±1，本版要求至少 3 只才计入平均 IC。

## 11. 常见问题

**Q：`doctor` 说找不到数据源**
在 `config.toml` 里填 `westock_dir`，指向包含 `scripts/index.js` 的目录（不是 `scripts/` 本身）。

**Q：下载有失败**
程序会自动重试一次，并在结尾列出失败代码。失败通常是接口限流，重跑 `python3 run.py fetch` 即可（已成功的文件会跳过）。确实拿不到的可以在 `data/universe.csv` 里删掉。

**Q：想换股票池**
`--index sh000905`（中证500）等，或改 `config.toml` 的 `universe_index`。换池后需要重新 `fetch`。

**Q：想加策略**
在 `quant/strategies.py` 的 `STRATEGIES` 里加一条，并在 `build_signals()` 里补一份 `{enter, exit, rank}`。引擎、检验、报告都会自动带上它。

**Q：回测能用来实盘吗**
不能直接用于实盘。它是一套研究工具，未计滑点、存在幸存者偏差、参数未做稳健性验证。任何策略在实盘前都需要独立验证。
